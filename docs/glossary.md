# Glossary

Plain-language definitions for every piece of jargon used in this
documentation. Terms are alphabetical.

- **Activation function** — the nonlinear bend (e.g. Tanh) applied inside
  the neural network so it can learn curves, not just straight lines.
- **Baseline** — the trusted numerical answer (`solve_bvp`) we compare the
  neural network against. Like an answer key.
- **BC (boundary condition)** — a rule the solution must obey at a wall,
  e.g. “temperature is 1 at the inner cylinder”.
- **Checkpoint** — a saved snapshot of the trained network
  (`checkpoints/*.pt`). Lets you stop, resume, or reuse a model later.
- **CLI (command-line interface)** — running the program by typing commands
  (`python main.py --mode train`) instead of clicking buttons.
- **Cleaning** — automatic tidying of datasets: removing broken rows,
  sorting, checking shapes. Always logged in a `*_cleaning_report.json`.
- **Collocation points** — random sample locations where the network is
  forced to obey the physics equations during training.
- **Config (YAML file)** — a human-readable settings file
  (`configs/*.yaml`) holding every number the program uses. Edit text,
  never code, to change an experiment.
- **CUDA** — technology letting the program use an NVIDIA graphics card to
  compute faster. Works automatically if present; otherwise the CPU is used.
- **Epoch** — one full training step. Thousands are needed; each one nudges
  the network slightly closer to obeying the physics.
- **Gate (R² > 0.95)** — the quality bar: a run PASSes only if the network
  matches the baseline with mean R² above 0.95.
- **Git / GitHub** — Git tracks file versions on your computer; GitHub
  hosts the shared copy online. `git clone` downloads it.
- **GPU/CPU** — the graphics card (fast, optional) vs the main processor
  (slower, always available) that runs the math.
- **LBFGS / Adam** — two built-in training algorithms (optimizers). Adam is
  the default; L-BFGS is a slower, precise finisher.
- **Loss** — a single number measuring “how wrong the network still is”.
  Training drives it down toward zero.
- **LTNE** — local thermal non-equilibrium: fluid and solid get *separate*
  temperatures (θf, θs) instead of sharing one.
- **Mock data** — reference datasets generated by the numerical solver
  (not experiments) used to check the network. See
  [Datasets](datasets.md).
- **MSE / RMSE / R²** — three standard scores comparing prediction vs
  answer: average squared error, its square root, and a 0-to-1 fit quality
  (1.0 = perfect).
- **PDE (partial differential equation)** — the physics equations themselves.
  The network learns by minimizing how much it violates them (the residual).
- **pip** — Python's installer tool: `pip install -r requirements.txt`
  fetches every library the project needs.
- **Python** — the programming language everything here is written in.
- **Repository (repo)** — the project folder with code, configs, docs and
  version history.
- **SHAP / LIME** — two explanation tools: SHAP says which *parameters*
  matter overall; LIME explains individual predictions locally.
- **Sweep** — automatically repeating runs over a grid of parameter values
  (e.g. M = 0, 1, 2) and collecting results in a CSV table.
- **Terminal (console/shell/command line)** — a window where you type text
  commands. See [Start here](start-here.md#step-0-what-is-a-terminal).
- **venv (virtual environment)** — an isolated private workspace for the
  project's libraries, so your system Python stays untouched. Recognizable
  by the `(.venv)` prompt prefix.
- **YAML** — a plain-text settings format (`key: value`). Indentation
  matters; use spaces, never tabs.
